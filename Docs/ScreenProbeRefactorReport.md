# 屏幕探针重构与验证（2026-11-04）

本次将运行时采样改为「每个降采样格一个发射点，刷新时统一 128 条射线」。
新路径不再使用相机距离决定的 2×2 / 4×4 二次共享，也不再区分近 32、远 128。
旧路径保留为 `sampling_mode: "legacy"`，便于对照和回退。

这是采样及重建架构的切换，不能据此宣称噪点已经解决或性能更好。
静止近景的时间波动下降，但仍有残余空间噪点，近景成本明显高于旧路径。

## 数据流

1. 每个 `trace_downsample_factor` 方格扫描有效可见像素，选最接近格中心的一个。
   降采样 8 表示每个 **8×8 内部渲染像素**格一个发射点；没有额外乘 4 或 16。
   DLSS Quality 下，本轮 2560×1600 实际输出捕获对应 1707×1067 内部渲染分辨率。
2. 一个发射点保留 8×8 等立体角半球方向格。128 条射线即每方向格两条。
   先存入射辐亮度 Li，不提前乘接收点余弦、不按命中数归一化。
3. 每条方向先做现有屏幕追踪；未命中时续查近处 Mesh SDF，再续查远处 Global SDF。
   这是一份方向预算，三个阶段不会各额外申请 128 条。
   Mesh SDF 保留近起点三角形确认，最小命中距离仍为零。
   黑色命中仍遮挡后方；未完成的近处查询不会被当作穿透许可。
4. 方向历史通过位置、法线、切线基和命中距离视差检查后累计，默认权重窗口 4 次有效刷新。
   静止且通过检查时采用两帧棋盘刷新；复用帧不增加历史样本计数。
   被复用的探针保留真正发射过射线的位置和法线，不把旧结果伪装成从新位置发射。
5. 在方向域做同方向 5×5 二项式滤波，探针步长 2。
   使用法线、对称切平面距离和命中距离视差控制权重。
   **空间滤波结果只用于显示与积分，不反馈进方向历史。**
6. 滤波后投影为世界空间二阶 SH（9 个 RGB 系数），做漫反射卷积。
   全分辨率像素使用自己的法线求值、自己的深度做几何匹配。
   没有沿用「先积分成一张低分辨率 RGB，再把法线差异一起放大丢掉」的中间方案。
7. 最终 RGB 使用全分辨率重投影、快慢历史及两遍 Atrous。
   慢历史上限保持 16；HistoryClamp 的统计步长改为探针间距，避免把同一噪声块的相邻像素
   误当作独立样本，低估方差并反复夹回当前噪声。
   重建缺乏兼容探针时先查邻近兼容探针，再复用经过单独验证的像素历史；无支持不算新的黑色观测。

## 最终配置

```json
"ssgi": {
  "enabled": true,
  "sampling_mode": "screen_probes",
  "screen_probes": {
    "rays_per_probe": 128,
    "history_updates": 4
  },
  "world_sampling": { "mesh_min_hit_distance": 0.0 },
  "trace_downsample_factor": 8,
  "intensity": 1
}
```

参数启动时读取。新路径只有一个射线数；它必须至少为 64 且为 64 的整数倍。
没有加入额外的任意射线上限，仍受整数表示、显存、纹理尺寸和执行时间约束。
方向图集宽高为探针网格宽高的 8 倍，超过 D3D12 的 16384 限制时会记录明确的分配失败信息。
例如 2560 宽的内部渲染分辨率配降采样 1 超出当前图集布局的宽度限制，不能声称任意分辨率都支持 1。

128 指每次真正刷新，不是每帧每点固定重追踪 128 条。
1706×1066、降采样 8 的静止近景有 28676 个有效发射点；第 128 帧 14338 个刷新、14338 个复用，
该帧配置射线量为 1835264。旧路径还叠加二次共享，射线预算远低于新路径，性能对比并非等预算。

DLSS、HBAO、CSM、世界探针烘焙及 SDF 精度配置没有为了获得结果而偷偷调整。
隔离测试关闭 AA/HBAO；实际输出测试保留 DLSS Quality/HBAO。两类结果分开记录。

## 隔离测试

相同 Cornell 场景及已有近景/全景机位，1706×1066、降采样 8、AA=None、HBAO 关闭。
旧路径使用改动前的近 32 / 远 128、世界历史 4、世界显示空间滤波 step 2。
每组运行 291 帧，比较第 256–287 帧。GPU 指标为整帧时间，排除前 32 帧及捕获帧，共 227 个样本。
原生 GI 导出均检查有限值；旧版低分辨率与新版全分辨率在共同的 214×134 分析网格上比较。

| 场景 | 旧版时间 RMS | 新版时间 RMS | 旧版 GPU 中位数 | 新版 GPU 中位数 |
|---|---:|---:|---:|---:|
| 静止近景 | 0.00026604 | 0.00013751 | 2.881 ms | 17.735 ms |
| 静止全景 | 0.00017984 | 0.00009366 | 8.801 ms | 10.243 ms |
| 近景平移 | 0.00034005 | 0.00018211 | 2.954 ms | 16.642 ms |

静止两机位时间波动约下降 48%；平移指标包含真实光照变化，不能直接解释为纯噪声降幅。
近景空间二阶差分 RMS 为旧版 0.00012171、新版 0.00020265，仍高于旧版；该指标也包含真实梯度，
这里不据此宣称「空间噪声下降」。全景边缘更锐利，但缺少高采样参考，不能宣称所有亮度差异都更正确。
当前小型 Global SDF 覆盖配置也原样保留，其离屏远处支持不足不会由重建架构自动消失。

参数试验固定射线数与历史长度：方向 3×3 → 5×5 step 1 → 5×5 step 2。
对应近景时间 RMS 约为 0.00029282、0.00023682、0.00013751。
选用最后一组，代价是更宽的滤波支持和约 1–2 ms 的额外近景成本；接触光照仍可能被软化。
这些是阶段性同变量试验，旧的低分辨率中间实现不作为最终结果。

| 辐亮度契约测试 | 结果 |
|---|---|
| 全方向恒定 Li=1 | 最终 E/π 最大绝对误差 0.003418，小于 0.005；无非有限值 |
| 全方向恒定 Li=0 | 最终 RGB 严格为零 |
| 世界烘焙缓存 | Debug 捕获的原始探针 SH SHA-256 与改动前一致 |

烘焙数据 SHA-256：`4b11f792827160fb8b476274aeeda35f0538601d93485ec6e7ad4fa2a4fd3b7c`。
恒定白色的小误差包括半球格点积分、SH 截断与 FP16 量化；本次没有做曝光补偿去强行对齐。

## 实际输出与原生验证

正式 Debug/Release 构建通过，现有编译及第三方 PDB 警告保留。
Debug 的近景、全景、171×109 奇数分辨率以及 SSGI-only/Mesh-SDF 预览通过调试层检查。
171×109、降采样 1 的额外 Debug 测试也通过：18639 个有效发射点，网格正好为 171×109，
没有隐藏的 2×2/4×4 二次分组。上述六组均为 0 个 D3D12 警告、0 个错误，
导出资源也通过 `Tests/AnalyzeScreenProbeGather.py` 的几何与有限值检查。
实际输出使用相同相机、2560×1600 输出、DLSS Quality、HBAO 开启；内部渲染 1707×1067。
每组运行 291 帧，排除最初 32 帧和单个捕获帧，258 个整帧 GPU 样本：

| 实际输出 | 旧版 GPU 中位数 / P95 | 新版 GPU 中位数 / P95 |
|---|---:|---:|
| 全景 | 12.078 / 13.618 ms | 13.355 / 14.600 ms |
| 近景 | 6.201 / 7.283 ms | 19.227 / 20.861 ms |

全景成本增加约 11%，近景约为原来的 3.1 倍；新近景约相当于 52 FPS 的 GPU 上限。
因此当前统一 128 的版本不能宣传成性能优化，也没有达到稳定 60 FPS 的近景目标。
保留用户指定的 128，没有偷偷减少射线或更改 DLSS 档位来掩盖成本。
实际完整渲染并列图位于 `tmp/screen-probe-refactor/actual-comparison.png`；
空间噪点和接触光照的主观取舍仍需要用户在运动中评估。

## 显存与限制

1706×1066、降采样 8 时，新探针 ping-pong 图集与位置/法线/receiver 数据合计约 29.54 MiB；
方向滤波临时图约 14.00 MiB，SH2 临时图约 1.97 MiB。
全分辨率快慢 RGB/深度/法线双缓冲另需约 97.12 MiB。
这些不是总显存：还存在重投影、Atrous、旧路径兼容资源、场景与世界 GI 缓存；
选择隔离诊断源也会按需分配独立预览历史。

一个格只能保留一个主要表面，刚出现的极细表面仍可能没有兼容探针。
当前采用邻近兼容探针修复和有效像素历史，没有自适应额外布点。
方向半球与 SH2 是漫反射近似，强法线扰动、遮挡边界、细接触光照仍有偏差。
这不是完整的 UE/AMD 实现，也没有替换现有世界空间辐亮度查询后端。

## 代码与复现

- `Shaders/ScreenProbeGather.hlsl`：布点、方向追踪、方向滤波、SH2 投影、逐像素解析。
- `Passes/ScreenProbeGather.inl`：RDG 资源依赖与阶段调度。
- `Passes/SSGIPass.h`、`Resources/ResourceManager.h`：模式分流、全分辨率历史、资源尺寸验证。
- `Resources/Settings_Manager.h`、`Resources/SSGIHybridState.h`：新配置与源变化失效。
- `Tests/AnalyzeScreenProbeGather.py`：读取真实 GPU 导出，检查 receiver 所属格、边缘格、方向图尺寸、
  有限值、历史状态、白/黑归一化。示例：

```powershell
python Tests/AnalyzeScreenProbeGather.py --geometry <metadata.json> --white <metadata.json> --black <metadata.json>
```

本轮隔离夹具、冻结着色器、相机、原始捕获及统计位于 `tmp/screen-probe-refactor/`。
`analysis.json` 为最终序列统计，`comparison.png`、`close.gif`、`motion.gif` 为实际捕获的并列展示。
`run-final.ps1` 记录正式二进制的隐藏验证命令；诊断序列程序仅在 tmp 下构建，不进入正式程序。

## 精确回退

保留降采样等其他配置，把 `ssgi` 恢复为下列改动前设置并重启：

```json
"ssgi": {
  "enabled": true,
  "sampling_mode": "legacy",
  "world_sharing": {
    "enabled": true,
    "accumulation_updates": 4,
    "spatial_filter": { "enabled": true, "step_width": 2 }
  },
  "world_sampling": {
    "near_distance": 2.0,
    "near_exit_distance": 2.2,
    "mesh_min_hit_distance": 0.0,
    "near_ray_count": 32,
    "far_ray_count": 128
  },
  "trace_downsample_factor": 8,
  "intensity": 1
}
```

只改 mode 而不恢复这些旧字段，会采用旧 loader 的缺省参数，不能算精确回退。

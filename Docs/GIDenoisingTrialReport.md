## 本轮采用的版本

采用 **world owner 的 4 批次时间积累**，已接入主工程并启用。它先稳定 Mesh/Global 的共享照明估计，再交给现有重建与最终像素历史。

此前 owner 到期后用一批新 RGB 完全替换旧 RGB；现在仅在真正追踪了新批次时，将其与通过原有几何重投影检查的旧 owner 混合。冷启动按实际批次数平均，成熟后新批次权重为 1/4。Mesh/Global 原有 2/4 帧刷新周期保留，所以 **4 批次不等于 4 帧**；它是有响应延迟的指数平均，不能当成四个独立样本的保证。

复用、重投影以及粗块复制不增加积累计数。无有效历史时直接使用当前估计；配置变化加入现有历史失效键。没有新增 GPU 纹理，也没有新增追踪射线。两组旧颜色暂存在组共享内存中。

原 owner atlas 被有意改为存积累结果，内部旧 `Raw` 名称保留绑定兼容，但捕获 metadata 已标记 `filtered_feedback` 和 `accumulation_updates`，不能再把开启时的 owner atlas 解释为未滤波观测。原始烘焙探针 SH 没有改动。

配置在 `Settings/Pipeline.json`：

```json
"world_sharing": {
  "enabled": true,
  "accumulation_updates": 4
}
```

改为 `1` 并重启，恢复原来的新批次直接替换逻辑。省略字段也默认 `1`。合法整数范围 1–32，本轮只比较了 1、4、8，没有声称 4 是所有场景的最优值。

主工程保留用户的降采样 **16**、world 近/远质量档 **16/64**、DLSS Quality、2560×1600、HBAO、近原点三角形确认及零盲区配置。本轮没有加回昂贵的逐插值贡献者墙体检查，没有延长最终像素的 16 次慢历史。

## 如何比较

- Cornell + Plain，同一场景、光源、烘焙参数。主机位使用先前第三张截图的相机；补一个第一张截图机位。
- 控制测试为 1280×800、AA=None、HBAO 关闭，world 预算 16/64；分别检查降采样 1、4、16。这些是独立测试目录的设置，未覆盖主工程设置。
- 21 组序列，每组运行 291 帧，抓取连续第 256–287 帧，共 672 次序列捕获。另做主工程集成的开/关及 Debug 捕获。
- 静止波动指标：最终 `gi-filtered` 的线性亮度在 32 帧间的逐像素标准差，再在同一 ROI 取 RMS。ROI 为图像去掉两像素边框，并非严格的可见表面蒙版。越低表示这段序列更稳，不能单独证明照明更准，也不能评价长期漂移。
- GPU 为整个渲染命令列表的时间戳统计，每组 227 个样本，排除前 32 帧及连续抓图帧；不含启动烘焙和 Present，**不是用户桌面帧率**。单次序列的小差异不作为加速结论。
- 256/256 射线版只作更高预算对照，它本身也有噪声，不能当真值。没有得到有效的逐帧 raw GI 序列，因此不报告 raw 方差。

| 主机位，降采样 4 | 0.000915 | 0.000389 | 57.5% | 7.056 → 7.042 ms |

## 其他试验为什么没有采用

以下均为主机位、降采样 4：

| 试验 | 静止波动 RMS | GPU 中位数 | 决定 |
|---|---:|---:|---|
| 原版 | 0.000915 | 7.056 ms | 基线 |
| 固定每子块代表点 | 0.000954 | 6.845 ms | 没有改善，不采用 |
| 按新批次轮换代表点 | 0.000932 | 6.923 ms | 没有改善，不采用 |
| 4 批次积累 | 0.000389 | 7.042 ms | 采用 |
| 8 批次积累 | 0.000207 | 7.085 ms | 更稳，但响应取舍更大，保留调参能力 |
| 轮换代表点 + 4 批次 | 0.000380 | 7.012 ms | 额外收益小，不增加这层复杂度 |
| 原版追踪预算升到 256/256 | 0.001174 | 24.900 ms | 本序列稳定性未改善，成本明显上升 |
| 接收面直接查询现有 L1 探针 | 0.000002 | 1.544 ms | 明显亮边、光照偏差，排除 |

直接探针诊断版没有配齐 DDGI 的方向可见性、探针重定位等机制，只能否定这个简单接法，不能据此否定成熟探针 GI。它对高预算对照均值的 RGB 距离为 0.01384，原版约 0.00203；视觉上墙角/接触处偏差明显。不能为了稳和快就采用。

单独导出当前机位的 screen SSGI，时间波动 RMS 仅约 0.0000166，且贡献很小。这支持本场景主要应先处理 world 路径；不能推广为所有机位的 SSGI 都无需降噪。

结果也修正了此前猜测：只固定/轮换空间代表点没有解决问题；在 world 共享层积累批次才有实测收益。不能把这次收益全部解释成代表点随机性的证据，更不能断言多射线永远没有帮助。

## 运动与响应取舍

在降采样 4 下额外比较固定速度 X 平移：每帧 0.004 m，共移动 0.192 m；抓取段四组的相机序列逐帧一致。对同轨迹 256/256 高预算序列的逐帧 RGB RMSE：

| 版本 | 对运动高预算序列的 RGB 距离 |
|---|---:|
| 原版 | 0.001452 |
| 4 批次 | 0.001339 |
| 8 批次 | 0.001509 |

因此选 4 作试用配置，而非直接选静止数字最小的 8。这个对照本身有噪声，不能把差异都称为拖影误差。运动期间的时间 RMS 包含真实画面变化，不能用它算“降噪百分比”。

[运动对照动图](../tmp/gi-noise-tuning/motion.gif)，以及 [抽帧对照](../tmp/gi-noise-tuning/motion-contact-sheet.png)。实际查看后，4 批次的地面/墙面随机斑块较弱，仍可见残余噪声。这段温和平移未覆盖急转、快速遮挡、移动物体或灯光突变；新光照响应可能变慢，没有声称无拖影。

## 接入验证与复现资料

- 主工程 Release、Debug 编译完成，MSBuild 编辑器 UI 架构检查通过；有既存编译警告，没有把它们描述为全工程零警告。
- 生产 Release 的 `accumulation_updates=4/1` 分别实跑捕获，元数据正确记录开/关；通过数值对照。与常量试验着色器不是逐位一致：开启版 RGB RMSE 约 `3.97e-7`、最大差 `3.05e-5`；关闭版 RMSE 约 `3.96e-6`、最大差 `1.37e-4`。配置版重新编译后的差异很小，不冒充 bitwise 相等。
- 开/关与原版、4/8 批次、高预算对照的原始探针记录 SHA256 均为 `4b11f792827160fb8b476274aeeda35f0538601d93485ec6e7ad4fa2a4fd3b7c`，确认收益不是换了烘焙数据。
- Debug 后台运行 259 帧，实际启用 D3D12 validation，0 warning、0 error；探针全部分类并完成目标更新。Release 控制序列没有启用 validation，不能拿它们的零计数替代 Debug 检查。
- 连续抓帧和相机运动只存在于隔离试验程序，已从主工程移除。最终生产代码只增加积累、配置/历史失效键和捕获语义说明。
- 尚未测主工程 2560×1600 + DLSS 的实际桌面帧率，也未做其它大场景验证。上述性能结论仅适用于控制场景。
